# Rust 编码规范

## 核心目标

- 保持改动小、边界清晰、依赖单向。
- 先复用现有模块、模式和工具，再写新抽象。
- 先用标准库，再用项目已有依赖，最后才新增依赖。
- 不为“以后可能需要”提前拆接口、工厂、配置或 helper(辅助函数)。

## 使用顺序

1. 先判断改动落在哪一层：workspace、crate、module(模块)、function(函数)。
2. 先找现有调用点、公共类型和已有模式，避免重写几行就能复用的逻辑。
3. 如果问题来自共享逻辑，优先修公共边界，不要在每个调用点各打一个补丁。
4. 只有当一段逻辑会复用、隔离了复杂边界、或独立命名能明显提升可读性时，再抽 helper。

## 分层与依赖方向

- 底层只放稳定模型、协议和通用类型；上层组合业务流程；最外层处理 CLI(命令行)、HTTP、数据库、文件系统等边界。
- 让依赖单向流动：共享类型 -> 核心逻辑 -> 适配层。客户端代码可依赖共享类型或协议，不反向依赖服务端实现细节。
- 明确 public API(公开接口) 和内部实现，默认保持私有，确实需要暴露时再 `pub`。
- 如果仓库存在生成代码或 `generated` 模块，修改生成源或构建脚本，不直接手改产物。

## 编码规则

- 默认把逻辑留在当前函数；不要预先抽取单次使用的 helper。
- 优先不可变数据；只有确实需要时才引入 `mut`。
- 能靠类型推导读清的地方不要补显式类型；公共 API、跨模块边界和复杂返回值再写清类型。
- 优先 `?`、`Option(可选值)` 和 `Result(结果类型)` 表达失败路径，不用 `unwrap()` 或 `expect()` 掩盖运行时错误；测试和启动期不变量断言除外。
- 优先 `iterator(迭代器)` 组合，如 `map`、`filter_map`、`collect`；如果 `for` 更直白，就用 `for`，不要为了函数式写难读代码。
- 只用一次的临时变量尽量内联，减少变量数量和作用域。
- 避免无意义解构；如果点语法更能保留上下文，直接 `foo.bar`。
- 避免 `use foo::*` 和导入别名；优先显式导入，命名空间需要时直接用模块名。
- 优先早返回和守卫分支，少写深层嵌套。
- 注释只解释非显然约束、性能权衡或外部协议坑点，不解释肉眼可见的赋值和流程。

## 复杂逻辑处理

- 主函数写 happy path(主路径)，把校验、解析、转换等支撑细节抽成紧邻的小函数，放在主函数下方。
- 不要把简单表达式切成一串单次使用 helper；只有当 helper 真正命名了一个概念时才抽。
- 同步解析、校验、选项组装保持同步；没有 `await` 就不要标 `async`。
- 能用强类型结构体表达的数据，不要退化成 `serde_json::Value`、`HashMap<String, Value>` 或字符串拼接协议。

## 命名与数据模型

- 模块、文件、函数、变量、字段使用 `snake_case`。
- 类型、枚举、trait(特征) 使用 `UpperCamelCase`。
- 常量使用 `SCREAMING_SNAKE_CASE`。
- 结构体字段默认保持 `snake_case`，让 `serde(序列化框架)`、数据库映射和生成代码尽量不写额外 rename(重命名)；只有外部协议不一致时再加 `#[serde(rename = "...")]` 等属性。
- 避免用 `dyn Any`、裸字符串 tag(标签) 或松散 map(映射) 代替可以建模的领域类型。

## 测试与质量门禁

- 少用 mock(模拟)；优先测真实实现和真实边界行为。
- 新功能至少补主路径测试，修 bug 必补回归测试。
- 测试不要复制实现逻辑，只验证输入输出和关键副作用。
- 非平凡逻辑至少留一个可运行检查：单元测试、集成测试，或最小 `#[test]` 回归样例。
- 默认质量门禁：
  `cargo fmt --all`
  `cargo check --all-targets`
  `cargo clippy --all-targets --all-features -- -D warnings`
  `cargo test --all-features`
- 多 crate 工作区优先在受影响 crate 或 workspace 根执行命令，遵循仓库现有约定。

## 快速判断

- 这段逻辑是否真的复用？不是，就先别抽。
- 这项能力标准库能做吗？能，就别加依赖。
- 这个错误应该暴露给调用方吗？应该，就返回 `Result`，别 `unwrap()`。
- 这层是否在反向依赖更高层实现？如果是，先改依赖方向。
- 这里是生成产物吗？如果是，去改生成源。
