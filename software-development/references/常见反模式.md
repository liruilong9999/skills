# 常见反模式

## 反模式 1：把《需求说明.md》写成实现方案

问题：

- 需求文档里直接出现框架、表名、函数名

修复：

- “做什么”留在《需求说明.md》
- “怎么做”放到《技术设计.md》和《接口契约》

## 反模式 2：还没稳定《接口契约》就开始实现

问题：

- 前后端边写边改字段，最后互相对不上

修复：

- 先固定《接口契约》，再让 Codex 按任务实现

## 反模式 3：一个任务塞给 Codex 太多内容

问题：

- 一个任务同时包含数据库、接口、页面、测试、发布

修复：

- 重新拆成《任务拆解.md》中的多个小任务

## 反模式 4：代码改了，文档没改

问题：

- 《数据模型.md》或《接口契约》已经过期

修复：

- 代码和文档一起更新
