# 软件开发工作流分阶段说明

## 阶段 0：项目基线

输出：`项目基线.md`

目标：

- 固定项目级规则
- 统一技术栈、架构原则和安全约束

在 Codex 中可这样请求：

```text
请基于当前项目生成《项目基线.md》，内容包括技术栈、架构原则、安全约束、目录规范、测试策略和禁止模式。
```

## 阶段 1：需求澄清

输出：`需求说明.md`

目标：

- 收敛需求
- 暴露假设
- 明确验收标准和范围边界

在 Codex 中可这样请求：

```text
请根据这段需求生成《需求说明.md》。
先列出关键假设，再整理用户故事、验收标准、异常场景、范围边界、非功能要求和待确认项。
```

## 阶段 2：测试设计

输出：

- `测试用例.md`

目标：

- 用测试约束后续设计
- 先覆盖主流程，再覆盖异常、边界、安全、性能和回归

在 Codex 中可这样请求：

```text
请基于《需求说明.md》生成《测试用例.md》。
先覆盖主流程，再补齐异常场景、边界条件、权限、安全、性能和回归检查点。
```

## 阶段 3：技术设计

输出：

- `技术设计.md`
- `数据模型.md`
- `接口契约/`
- 可选 `预研记录.md`

目标：

- 把需求映射为可落地设计
- 让设计满足全部测试
- 固定关键接口和数据边界

在 Codex 中可这样请求：

```text
请基于《需求说明.md》《测试用例.md》和《项目基线.md》生成《技术设计.md》《数据模型.md》以及《接口契约》目录下的文档。
```

## 阶段 4：任务拆解

输出：

- `任务拆解.md`

目标：

- 把设计和测试拆成 Codex 可以单步执行的任务

在 Codex 中可这样请求：

```text
请基于《技术设计.md》《数据模型.md》《接口契约》和《测试用例.md》生成《任务拆解.md》。
每个任务都要足够小，并补充依赖关系、对应测试和验证方式。
```

## 阶段 5：实现与测试

这一阶段没有内置命令。

正确做法是把当前任务和相关文档发给 Codex，例如：

```text
请根据《任务拆解.md》中的 TASK-003 实现当前任务。
请参考《需求说明.md》中的相关验收标准、《测试用例.md》中的相关测试、《技术设计.md》中的相关设计、《数据模型.md》中的相关实体，以及《接口契约》中的相关接口文档。
先完成测试，再完成实现。
```

## 阶段 6：验证与交付

输出：

- 验证结论
- 可选 `发布检查清单.md`

在 Codex 中可这样请求：

```text
请对照《需求说明.md》《测试用例.md》《技术设计.md》《数据模型.md》和《接口契约》检查当前实现是否一致。
如适合发布，请补一份《发布检查清单.md》。
```

## 多智能体并行开发

适合中大型功能或多模块改动。

建议步骤：

1. 先基于《任务拆解.md》划分独立任务包
2. 每个任务包分配一个智能体负责
3. 为每个智能体创建独立 Git 分支，例如 `codex/task-001-api`、`codex/task-002-ui`
4. 各分支并行开发并各自完成本地验证
5. 按依赖顺序合并到主分支或集成分支
6. 最后执行一次全量回归和交付验证

## 变更管理

需求变化时的顺序：

1. 更新《需求说明.md》
2. 更新《测试用例.md》
3. 必要时更新《技术设计.md》《数据模型.md》《接口契约》
4. 更新《任务拆解.md》
5. 再推进实现
