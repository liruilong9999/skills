# Codex 提示词模式

## 生成《项目基线.md》

```text
请基于当前项目生成《项目基线.md》。

要求：
1. 使用中文
2. 包含技术栈、架构原则、安全约束、目录规范、测试策略和禁止模式
3. 对不确定项使用 [待确认] 标记
```

## 生成《需求说明.md》

```text
请根据下面的需求生成《需求说明.md》。

先输出你对这个需求的关键假设，再整理：
- 功能概述
- 用户故事
- 验收标准
- 异常与边界场景
- 非功能要求
- 范围边界
- 待确认项

要求：
1. 使用中文
2. 不写具体实现细节
3. 验收标准尽量可验证
```

## 生成《测试用例.md》

```text
请基于《需求说明.md》生成《测试用例.md》。

要求：
1. 使用中文
2. 先覆盖主流程，再覆盖异常、边界、权限、安全、性能和回归场景
3. 测试要全面，不能只写 happy path
4. 后续《技术设计.md》必须以这些测试为约束
```

## 生成《技术设计.md》《数据模型.md》《接口契约》

```text
请基于《需求说明.md》《测试用例.md》和《项目基线.md》生成以下文档：
- 《技术设计.md》
- 《数据模型.md》
- 《接口契约》目录下的接口文档

要求：
1. 每条核心需求都能映射到设计落点
2. 每条核心测试都能在设计中找到支撑
3. 接口文档包含成功和失败响应
4. 数据模型包含字段、约束、索引和迁移说明
```

## 生成《任务拆解.md》

```text
请基于《技术设计.md》《数据模型.md》《接口契约》和《测试用例.md》生成《任务拆解.md》。

要求：
1. 每个任务都适合一次 Codex 会话完成
2. 标明依赖关系
3. 提供验证方式
4. 测试任务优先于实现任务
```

## 让 Codex 实现单个任务

```text
请根据《任务拆解.md》中的 TASK-xxx 实现当前任务。

请参考：
- 《项目基线.md》
- 《需求说明.md》相关章节
- 《测试用例.md》相关章节
- 《技术设计.md》相关章节
- 《数据模型.md》相关章节
- 《接口契约》中的相关文档

要求：
1. 只实现当前任务范围
2. 先完成对应测试，再完成实现
3. 如发现文档冲突，先指出冲突再处理
```

## 制定多智能体并行开发策略

```text
请基于《任务拆解.md》制定多智能体开发方案。

要求：
1. 按任务依赖把工作拆给多个智能体
2. 为每个智能体分配独立 Git 分支名称
3. 标明哪些任务可并行，哪些任务必须串行
4. 给出最终合并顺序、冲突风险和总体验证步骤
```

## 让 Codex 做交付验证

```text
请对照《需求说明.md》《测试用例.md》《技术设计.md》《数据模型.md》和《接口契约》检查当前实现。

请输出：
1. 一致性检查结果
2. 剩余风险
3. 是否建议补《发布检查清单.md》
```
