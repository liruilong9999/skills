# AI 协作模式

## 单任务上下文

每次只把一个任务交给 Codex，并附上最相关的文档片段：

- 《任务拆解.md》中的当前任务
- 《需求说明.md》中的相关验收标准
- 《测试用例.md》中的相关测试
- 《技术设计.md》中的相关设计
- 《数据模型.md》中的相关实体
- 《接口契约》中的相关文档

## 双角色模式

高风险任务可分两轮：

1. 先让 Codex 生成实现
2. 再让 Codex 以审查者身份只找问题，不重写

## 多智能体并行开发模式

适合任务边界清晰、依赖关系可控的需求。

推荐做法：

1. 先基于《任务拆解.md》把任务分成多个独立工作包
2. 给每个工作包分配一个智能体
3. 每个智能体使用单独 Git 分支开发
4. 各自完成代码、测试和局部验证
5. 由主智能体或集成智能体统一合并分支
6. 合并后执行总体验证和回归测试

分支建议：

- `codex/task-001-api`
- `codex/task-002-ui`
- `codex/task-003-test`
- `codex/integration`

分配原则：

- 同一核心文件不要交给多个智能体同时修改
- 强依赖任务保持串行
- 公共契约和数据结构先合并，再让下游任务继续

## 变更模式

需求变化时，先更新：

1. 《需求说明.md》
2. 《测试用例.md》
3. 《技术设计.md》或《数据模型.md》
4. 《接口契约》
5. 《任务拆解.md》

再进入代码实现。
