# 软件开发工作流速查表

## 产物命名

```text
项目基线.md

功能设计/[功能名称]/
├── 需求说明.md
├── 测试用例.md
├── 技术设计.md
├── 数据模型.md
├── 接口契约/
├── 任务拆解.md
├── 预研记录.md
├── 决策记录.md
└── 发布检查清单.md
```

## Codex 使用方式

不是执行命令，而是给 Codex 明确请求。

| 阶段 | 对 Codex 怎么说 | 输出 |
|---|---|---|
| 项目基线 | 请生成《项目基线.md》 | `项目基线.md` |
| 需求澄清 | 请生成《需求说明.md》 | `需求说明.md` |
| 测试设计 | 请生成《测试用例.md》 | `测试用例.md` |
| 技术设计 | 请基于《测试用例.md》生成《技术设计.md》《数据模型.md》和《接口契约》 | 设计文档 |
| 任务拆解 | 请生成《任务拆解.md》，并把测试任务前置 | `任务拆解.md` |
| 实现与测试 | 请根据 `TASK-xxx` 先写测试再实现当前任务 | 代码与测试 |
| 验证与交付 | 请核对实现并补《发布检查清单.md》 | 验证结果 |

## 最小规则

- 《需求说明.md》未过评审，不进入设计
- 《测试用例.md》未完整，不进入设计
- 《技术设计.md》与《接口契约》未稳定，不进入实现
- 《任务拆解.md》未拆小，不直接交给 Codex 大批量写代码
- 并行开发时，一个智能体一个分支，合并后统一回归
- 需求变更时先更新文档，再改实现
