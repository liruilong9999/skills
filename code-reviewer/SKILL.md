# 独立代码审查

本 skill 供“独立审查代理”使用：只读审查他人编写的代码变更并输出结论；不修改代码、不自我审查、不递归发起审查。

## 使用前提

- 仅当以独立审查代理身份审查“其他代理或他人编写”的代码时使用。
- 若审查对象是本代理自己刚写的代码，禁止自我审查：不得使用本 skill，应告知主代理通过 spawn_agent（fork_turns="none"）创建独立审查代理执行。
- 审查全程只读：禁止修改、新建、删除任何文件。

## 防递归边界（硬性规则）

- 禁止创建子代理。
- 禁止再次加载本 skill 或发起新的审查。
- 发现需要修复的问题时只报告，不代改，不进入“编码→再审查”循环。
- 输出结论后任务即结束。

## 审查输入

主代理应提供以下材料，缺失时先说明缺失项，不猜测：

- 需求或变更说明
- 变更文件清单或 git diff
- 影响域分析
- 变更预算（允许改什么、禁止改什么）
- 测试结果（三层测试：当前功能、关联功能回测、业务闭环）

## 审查清单

逐项核查，每项输出：结论（通过/不通过/存疑）、证据（文件:行号）、说明。

1. 变更预算：只改了允许范围，无顺手重构、无超范围修改
2. 影响域：覆盖调用方、依赖方、配置与构建脚本
3. 承重墙：是否触碰项目 AGENTS.md 标注的高风险区域，有无降级预案
4. 正确性：逻辑、边界条件、资源释放、错误处理
5. 三层测试兜底：当前功能测试、关联回测、业务闭环测试齐全且通过
6. 编码规范：按项目语言遵循对应规范（C++/Qt 用 cpp-qt-style；Python 用 python-dev-standards；TypeScript 用 typescript-agent-engineer）；库不处理业务、插件处理业务
7. 文档要求：中文文档、术语首次出现带括号解释、流程图用中文
8. 构建与集成：编译通过、沿用既有 cmake 风格、有 .codegraph 时已执行 codegraph sync

## 输出格式

```
结论：PASS / FAIL / 需要补充材料

问题清单：
- [P0/P1/P2] 文件:行号 — 问题描述 — 建议

通过项摘要：
- ...
```

问题分级：

- P0 阻断：安全、数据丢失、明显逻辑错误
- P1 应修复：逻辑缺陷、规范不符
- P2 建议：可延后的改进

## 结束

输出结论后直接结束；不修改代码、不创建子代理。
